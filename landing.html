The ethos

Four load-bearing properties

1

Markdown under git

Every byte of memory is readable markdown. Audit with cat. Review in git diff. No binary indexes, no vector DBs.

2

No runtime

Hooks fire and exit. No daemon, no server, no worker. The system disappears into the file tree between sessions.

3

Gated promotion

Every fact in durable memory has a written Why accepted: rationale committed in git. The diff is the audit trail.

4

Local, no telemetry

State about your project lives in your repo. State about you doesn't accumulate anywhere. Single-user, local-only.

Quick start

One block to copy-paste

# Clone the kit + initialize your project + generate agent configs
git clone https://github.com/aommi/agent-memory-kit.git .agent/memory-kit && \
  python3 .agent/memory-kit/generate.py init && \
  python3 .agent/memory-kit/generate.py all

Creates memory/semantic.md, memory/candidates.md, DECISIONS.md, CLAUDE.md, AGENTS.md — everything your agents need to remember. MIT licensed.

What the agent sees

Self-documenting files

The generated CLAUDE.md and AGENTS.md tell each agent exactly how to use memory — what to read, when to write, how to promote. No README required. The instructions are in the files the system generates.

### Memory Discipline

- `memory/semantic.md` — distilled project knowledge
- `memory/candidates.md` — staged lessons awaiting promotion

**Stage → Graduate promotion:**
- Append claims to candidates.md with a Staged date and Sources
- Graduate: move to semantic.md with **Why accepted:** rationale
- Reject: move to candidates.rejected.md with **Why rejected:**

Choosing a tool

Not every memory system is for everyone

Three projects in the same space, three different philosophies. Pick the one that matches how you work.

Agent Memory Kit gbrain agentic-stack
Storage Markdown in git Postgres + pgvector JSONL + FTS5
Search grep Hybrid vector + keyword + graph FTS5 full-text
Runtime None (hooks fire & exit) MCP server, worker, jobs queue TUI, dashboard, dream cycle
Install Copy folder bun install brew install
Promotion gate Written rationale per entry Auto-escalation by mention count Auto-detect + graduate script
Auditability git diff Database + dashboard JSONL exports + dashboard
Multi-agent 8 agents, shared files MCP tools (30+) 10+ harness adapters
Best for Solo devs who want memory to last as long as the repo Power users who need retrieval quality and autonomous synthesis Teams who want a polished multi-agent experience with monitoring

All three are open source. The right choice depends on whether you value legibility, retrieval, or polish.

Legibility compounds.
Infrastructure decays.

A markdown file readable in a git diff five years from now is a different kind of asset than an embedding index whose schema you no longer remember.
