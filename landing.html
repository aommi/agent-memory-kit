The ethos

Four load-bearing properties

1

Markdown under git

Every byte of memory is readable markdown. Audit with cat. Review in git diff. No binary indexes, no vector DBs, no opaque state.

2

No runtime

Hooks fire and exit. No daemon, no server, no worker. The system disappears into the file tree between sessions.

3

Gated promotion

Every fact in durable memory has a written Why accepted: rationale. The diff is the audit trail. No silent auto-graduation.

4

Local, no telemetry

State about your project lives in your repo. State about you doesn't accumulate anywhere. Single-user, local-only.

Quick start

Five commands to working memory

git clone https://github.com/aommi/agent-memory-kit.git
cd your-project
cp -r ../agent-memory-kit .agent/memory-kit
python .agent/memory-kit/generate.py init    # answer 5 prompts
python .agent/memory-kit/generate.py all     # generates configs for your agents

Creates memory/semantic.md, memory/candidates.md, DECISIONS.md, CLAUDE.md, AGENTS.md — everything your agents need to remember.

What the agent sees

Self-documenting files

The generated CLAUDE.md and AGENTS.md tell each agent exactly how to use memory — what to read, when to write, how to promote. No README required. The instructions are in the files the system generates.

### Memory Discipline

- `memory/semantic.md` — distilled project knowledge
- `memory/working.md` — live task scratchpad
- `memory/candidates.md` — staged lessons awaiting promotion

**Stage → Graduate promotion:**
- Append claims to candidates.md with a Staged date and Sources
- Graduate: move to semantic.md with **Why accepted:** rationale
- Reject: move to candidates.rejected.md with **Why rejected:**
